# 从本机记忆空间接班

用户指定项目后，先读取适用规则，再读该项目 README 和 STATUS；已在上下文且未变化的不重复读。STATUS是唯一当前执行状态。不要把历史档案里的“暂停”“计划”或旧快照提升为今天的任务；若项目定位或授权范围缺失，集中询问缺项，仍可先完成明确范围内的只读检查。

用 `bootstrap.py doctor [--config <connection>]` 核对现有连接的store_id/schema/revision；未知或冲突时停止业务写入。不要加载安装资料、整份历史、原始聊天或全库来恢复上下文。根据STATUS里明确缺少的对象/决策，以 `memory_sync.py [--config <connection>] search --query "关键词" --limit 5` 检索，再针对稳定ID读取history。此v1.0.1基线的history会返回该对象全部历史；对象很大时先让执行者选择最小需要的证据，不能宣称已有分页预览。

汇报当前任务、直接证据、开放缺口和下一步。历史回答附来源ref、时间及不确定性；不同名字不证明同对象，同名也不自动合并。没有证据的原因保持未知。需要新记录时沿用统一apply接口与request_id，不建立另一套数据库或把项目状态复制到档案维护。

本包不包含三文档受控写回原型、上游RelayTeam文件或AGENTS模板，不自动修改STATUS/HANDOFF/摘要。任意项目格式尚未适配；需要安全写回时，应先审查原项目格式、保护要求和用户授权，再选择兼容工具。不能把模拟三文件试验当作正式项目部署通过。
